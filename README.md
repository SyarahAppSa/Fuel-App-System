# فيول آب — منصة نقل وإدارة الوقود للشركات (المرحلة الأولى: التجربة التشغيلية)

منصة سعودية متعددة الشركات تربط **سوق نقل الوقود** (مستند أرامكو ← ناقل ← صهريج ← تسليم) بـ**إدارة الوقود داخل مواقع العميل** (خزانات ← تزويد المعدات بشرائح NFC)، مع تتبع كل لتر من المستند حتى المعدة.

> **معيار العرض محقق:** يفتح مدير الشركة تقرير معدة (`/assets/:id`) فيرى من زوّدها ومتى وكم لترًا، ومصدر اللترات (خزان ← رحلة الاستلام ← مستند أرامكو، أو تزويد مباشر ← الرحلة ← الطلب ← المستند)، والمشروع ومركز التكلفة وقت التنفيذ، والتكلفة.

جميع البيانات المرفقة **تجريبية** ومعلّمة بذلك في الواجهة والتقارير.

## النسخة التجريبية المنشورة

**https://fuel-app-system.onrender.com** — تُنشر تلقائيًا مع كل دفع إلى `main`. على الخطة المجانية: أول فتح بعد خمول قد يستغرق نحو دقيقة، والبيانات تعود للبيانات التجريبية عند كل إعادة تشغيل أو نشر.

### وضع العرض المفتوح (بلا كلمة مرور)
عند ضبط متغير البيئة `FUELAPP_OPEN_DEMO=1` يفتح الرابط مباشرة على بوابة إدارة فيول آب دون بريد أو كلمة مرور، مع تبديل لأي حساب تجريبي بضغطة. **مفعّل على النسخة المنشورة فقط** لأن بياناتها تجريبية؛ مغلق افتراضيًا، ويقتصر على الشركات الموسومة تجريبية. لإيقافه احذف المتغير من إعدادات Render.

## مركز تشغيل الإدارة
الصفحة الرئيسية لحساب الإدارة: مؤشرات الطلبات والرحلات والشركات والسائقين والصهاريج والوقود والمالية بفلاتر الفترة والشركة والمنطقة والمشروع ونوع الوقود، وكل رقم يفتح سجلاته. صفحة لكل شركة، وبحث موحد، وتقارير Excel/PDF، وسجل تدقيق. التفاصيل والتعريفات وحسابات المراجعة: `docs/ADMIN.md`.

## التشغيل

المتطلبات: Node.js 22.13 أو أحدث (يستخدم SQLite المدمج `node:sqlite` — بلا خدمات خارجية).

```bash
npm install
npm run build      # يبني واجهة الويب
npm run seed       # ينشئ قاعدة البيانات والبيانات التجريبية (يحذف القديمة)
npm start          # http://localhost:3000
npm test           # 24 اختبارًا: القبول الإلزامي + سيناريو المالك + العقود والباقات والسعة
```

للتطوير: `npm start` في نافذة و`npm run dev:web` في أخرى (Vite على 5173 مع توجيه `/api`).

متغيرات البيئة: `PORT`، `FUELAPP_DB` (مسار قاعدة البيانات)، `FUELAPP_UPLOADS` (مجلد الملفات الخاصة).

### سيناريو التجربة الكامل (جرّبه بنفسك)
1. **client1@fuelapp.demo** ← المشاريع والمواقع: أضف مشروعًا ثم موقعًا (مدينة الرياض) ثم خزانًا؛ ثم المعدات ← إضافة أصل على الموقع الجديد.
2. طلبات النقل ← «تنزيل مستند أرامكو تجريبي (20,000 لتر)» ← ارفعه ← اعتمد البيانات ← اختر الموقع والخزان والكمية 20,000 ← قارن الناقلين ← اختر «ناقلات الوسطى» بالسعر المنشور ← أرسل.
3. **carrier1@fuelapp.demo** ← افتح الطلب ← قبول ← إسناد الصهريج «أ ب ج 4512» والسائق محمد القحطاني.
4. **driver1@fuelapp.demo** من الجوال ← الرحلة ← الحالات والصور الأربع والكميات.
5. **client1** ← الرحلة ← «رابط محدود لمستلم الموقع» ← فتح ← تأكيد ← الخزان 20,000.
6. **fuel1@fuelapp.demo** ← شرائح NFC ← ربط شريحة بأصل (اختر أي شريحة «في العهدة» من المحاكي) ← التزويد ← الخزان ← المحاكي ← 200 لتر.
7. **client1** ← المعدات ← المعدة ← اضغط عملية الـ200 لتر ← تتبع: الخزان ← الرحلة ← الطلب الأصلي. صدّر Excel من سجل التزويد وPDF من صفحة الرحلة.

نتيجة تنفيذ هذا السيناريو آليًا وعبر المتصفح: `docs/SCENARIO-RESULT.md` والصور في `docs/scenario/`.

## ما تم تنفيذه في المرحلة الأولى

- **الأطراف والاعتماد:** شركات عميلة/ناقلة، وثائق بتواريخ صلاحية، اعتماد أو إيقاف من إدارة فيول آب؛ إيقاف ناقل يحيل رحلاته الجارية فورًا لمراجعة تشغيلية.
- **الأسعار والأسطول:** أسعار مسار ثابتة أو لكل 1000 لتر، رسوم انتظار وإلغاء، تغطية تحميل منفصلة عن تغطية التسليم، صهاريج بسعات ومنتجات وصلاحية وثائق، سائقون برخص.
- **مستند أرامكو:** رفع PDF مع فحص التوقيع الفعلي للملف، استخراج (رقم المستند، نقطة التحميل، المنتج، الكمية، التواريخ) بدرجة ثقة لكل حقل، عرض جنبًا إلى جنب مع الملف، إدخال يدوي للممسوح ضوئيًا، كشف الرفع المكرر بالبصمة، منع اعتماد الرقم مرتين، وحساب المصرح/المحجوز/المحمل/المسلّم/الملغى/المتاح مع منع تجاوزه.
- **السوق والحجز:** بحث عن الناقلين المؤهلين والمتاحين، تفصيل السعر (أجرة + خدمة فيول آب + ض.ق.م 15%)، أداء الناقل على المسار مع حجم العينة، نسخة سعر محفوظة، مهلة قبول، قبول/رفض بسبب، إسناد مع فحص السعة والمنتج والوثائق والرخصة والتداخل الزمني داخل معاملة واحدة.
- **السائق:** تطبيق ويب ميداني بالحالات الكاملة + التوقف والاستئناف، الصور الأربع (زوج تحميل للرحلة وزوج تفريغ لكل نقطة)، الموقع ووقت الالتقاط ووقت الخادم، **صندوق صادر IndexedDB للعمل دون اتصال** مع معرف عملية ثابت يمنع التكرار، وعرض المرفوع/المعلق/الفاشل.
- **الاستلام:** تأكيد أو اعتراض من حساب المستلم أو **رابط محدود الصلاحية بلا حساب**؛ الاعتراض/الفرق/الإثبات الناقص ← «بانتظار المراجعة» ← قرار مخول ← إغلاق.
- **المخزون:** دفتر حركات موحد (افتتاحي، استلام، صرف، تحويل بحركتين، مرتجع، تسوية، تصحيح)، رصيد دفتري من الحركات المعتمدة، جرد بفرق يتطلب موافقة، متوسط مرجّح للتكلفة، والتكلفة المجهولة تظهر «غير متوفرة» لا صفرًا.
- **التزويد المباشر:** دفعة مخصصة عند وصول الصهريج لا تدخل خزان الموقع؛ كل تعبئة NFC مرتبطة برحلة المصدر، والمصروف + المتبقي = الدفعة.
- **NFC:** دفعات وعهدة، ربط مع تحقق من رقم الأصل واختبار قراءة، شريحة نشطة واحدة لكل أصل (فهرس فريد جزئي)، إيقاف/فقد/تلف/استبدال بسجل كامل، قراءة فعلية عبر **Web NFC** على Chrome Android + محاكي للعرض + إدخال المعرف، تحقق خادمي (الحالة، صلاحية المشغّل، الموقع/المشروع، نوع الوقود، سقوف العملية/اليوم/الشهر، رصيد المصدر، العداد) وتسجيل كل محاولة مرفوضة، QR/يدوي كاستثناء مسجل، تنبيه العمليات المتقاربة وتراجع العداد.
- **التصحيح:** لا تعديل للعملية المعتمدة؛ حركة تصحيح مرتبطة بسبب، من دور غير المنفذ، على المشروع الأصلي. نقل الأصل بتاريخ نفاذ لا يغير التقارير التاريخية.
- **التقارير:** لوحة مؤشرات قابلة للنقر حتى السجلات، تقرير المعدة، سجل التزويد مع تصدير CSV (UTF-8 لفتحه في Excel)، تقرير توثيق التعبئة والتسليم العربي القابل للطباعة PDF مع الصور الأربع، مطابقة دورة الوقود، رقابة الشرائح، كميات المستندات. «بيانات غير كافية» عند تعذر الحساب.
- **الصلاحيات والتدقيق:** 10 أدوار، عضويات متعددة لنفس المستخدم، نطاق مشروع/موقع، إخفاء السعر والمستلم والمستند عمّن لا يحتاجه (بما فيه الناقل قبل القبول)، وصول مؤقت للملفات مع سجل اطلاع، سجل تدقيق للعمليات الحساسة، إشعارات مرتبطة بمفتاح العملية فلا تتكرر.

## العقود والباقات وحجز السعة (منفذة)
- **عقد شهري/سنوي** يقترحه العميل ويوافق عليه الناقل: أسعار لكل مسار ومنتج، سعة مضمونة شهريًا، مستوى خدمة (% في الموعد)، تجديد تلقائي، وشروط ناقل بديل بسقف فرق سعر. سعر العقد يظهر في السوق تلقائيًا ضمن مدته، ويظهر تجاوز السعة المضمونة والإخلال بمستوى الخدمة.
- **باقة رحلات** مدفوعة مسبقًا: إجمالي/محجوز/منفذ/متوافر، حد لترات الرحلة، صلاحية، وتوزيع على المشاريع. القواعد: **يُحجز** الرصيد عند إنشاء الطلب، **يُخصم** عند التسليم، **يعود** عند الإلغاء قبل قبول الناقل أو رفضه، والإلغاء بعد القبول **يُخصم** إن نصت الباقة. سجل حركة لكل رحلة ولا خصم مزدوج.
- **حجز سعة** لمنطقة ومنتج وفترة بعدد رحلات موزع على المشاريع: فحص سعة الناقل (صهاريج مؤهلة × أيام − حجوزات متداخلة) وإظهار التعارض عند الطلب، ورفض التأكيد عند عدم كفاية السعة، وربط الطلبات ضمن الفترة تلقائيًا مع كشف تجاوز حصة المشروع.

## NFC
المسار يعمل بقراءة فعلية على Chrome Android أو بمحاكاة واضحة على أي جهاز. العتاد المطلوب للاختبار الفعلي وخطة الاختبار: `docs/NFC-HARDWARE.md`.

## قيود معروفة يجب معالجتها قبل الإنتاج
- SQLite مناسب للتجربة؛ للإنتاج انقل المخطط إلى PostgreSQL (المخطط علائقي قياسي ومعاملاته صريحة).
- الملفات تُحفظ على القرص المحلي؛ في الإنتاج استخدم تخزين كائنات خاص بروابط موقعة قصيرة الأجل بدل `?token=` في الروابط.
- استخراج PDF يعمل داخل طلب الرفع؛ انقله لطابور خلفي مع فحص فيروسات حقيقي.
- لم تُجرَ اختبارات الحمل (10 آلاف شركة / 10 ملايين عملية) ولا اختبار NFC على معدات فعلية — هذه بنود الاختبار 10.

راجع `docs/ARCHITECTURE.md` لخرائط الشاشات ومصفوفة الأدوار ونموذج البيانات وقواعد الحالات.
