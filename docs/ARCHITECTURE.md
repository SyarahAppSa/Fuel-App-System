# فيول آب — البنية وقواعد العمل

## 1. البنية التقنية

```
web/ (React + Vite، RTL، PWA)          server/ (Node 22 + Express)
 ├─ لوحة الشركة العميلة                 ├─ app.js        المسارات وفحص الصلاحيات
 ├─ لوحة الناقل                         ├─ auth.js       الجلسات، الأدوار، نطاق المشروع
 ├─ تطبيق السائق (ميداني)               ├─ services/trips.js      السوق، الطلب، الرحلة، الإسناد، التسليم
 ├─ جلسة التزويد NFC (ميداني)            ├─ services/inventory.js  دفتر الحركات، الخزانات، الدفعات
 ├─ إدارة فيول آب                          ├─ services/fueling.js    NFC، التفويض، التزويد، التصحيح
 ├─ رابط المستلم /r/:token              ├─ services/documents.js  الملفات الخاصة، PDF، الاستخراج
 └─ outbox.js صندوق صادر IndexedDB      ├─ services/reports.js    المؤشرات والتقارير وتقرير PDF
                                        └─ schema.sql   SQLite (WAL، مفاتيح أجنبية، معاملات BEGIN IMMEDIATE)
```

**الوحدات:** الكميات بالملّيلتر (عدد صحيح)، المبالغ بالهللة (عدد صحيح)، الأوقات UTC وتعرض بتوقيت الرياض.

## 2. السجلات الثلاثة المترابطة

| السجل | الجداول | ما يجيب عنه |
|---|---|---|
| الطلب والرحلة | `orders`, `trips`, `trip_stops`, `trip_events`, `trip_photos`, `assignment_history` | ماذا اتُّفق عليه، بأي سعر، من حمّل وسلّم، ومتى |
| الاستلام والمخزون | `fuel_batches`, `fuel_movements`, `stock_counts` | كم دخل كل خزان أو دفعة وكم خرج وكم بقي |
| عملية تزويد الأصل | `fuelings`, `authorization_attempts`, `nfc_tags`, `nfc_tag_events` | كم استلمت كل معدة، من أي مصدر، بأي تحقق، على أي مشروع وتكلفة |

اللتر يظهر **مرة واحدة** في الاستهلاك: الاستلام في الخزان حركة `receipt`، والصرف حركة `issue` سالبة مرتبطة بعملية التزويد. في التزويد المباشر تُنشأ دفعة `direct` بحركة `direct_allocation` ولا تلمس أي خزان.

## 3. قواعد الحالات

**الرحلة:** `awaiting_acceptance → awaiting_assignment → assigned → to_loading → at_loading → loaded → to_delivery → at_site → (to_delivery لنقطة تالية) → delivered → closed | under_review → closed`
مسارات جانبية: `rejected` (من الناقل بسبب)، `cancelled` (من العميل قبل التحميل، يحرر الحجز ويطبق رسوم الإلغاء بعد القبول)، `on_hold` ↔ استئناف للحالة السابقة، `reassigned` قبل التحميل.
- كل انتقال `UPDATE ... WHERE status = <الحالة السابقة>`؛ أي تزامن يفشل بـ 409.
- الإغلاق يتطلب: تأكيد كل نقاط التسليم + فرق التحميل/التسليم ضمن 20 لتر أو 0.2% + الصور كاملة. وإلا `under_review` مع استثناء.
- الاستثناء المعتمد لا يُعاد فتحه.

**نقطة التسليم:** `pending → arrived → delivered → confirmed | disputed`. الاستلام في المخزون يُنشأ عند `confirmed` أو عند اعتماد الاعتراض بالكمية المقبولة.

**الشريحة:** `in_custody → pending_activation → active ↔ suspended`؛ `lost | damaged | replaced` نهائية. فهرس فريد جزئي يمنع شريحتين نشطتين لأصل واحد.

**عملية التزويد:** `approved` (مع حركة صرف) | `rejected` (تعارض مزامنة، بلا حركة) | تصحيح = سجل جديد `corrects_fueling_id` بكمية فرق موجبة أو سالبة.

## 4. منع الازدواج والتزامن

| الخطر | الحماية |
|---|---|
| تكرار عملية تزويد من جهازين/إعادة إرسال | `fuelings.client_op_id UNIQUE` + فحص داخل المعاملة |
| تكرار حدث أو صورة من السائق | `trip_events.client_op_id` و `trip_photos.client_op_id` فريدة |
| حجز صهريج/سائق لرحلتين متداخلتين | فحص التداخل داخل `BEGIN IMMEDIATE` |
| تجاوز كمية المستند | حساب المتاح داخل معاملة إنشاء الطلب |
| تكرار الطلب بضغطتين | `orders.idempotency_key` |
| تكرار إشعار عند إعادة المحاولة | `notifications.source_key UNIQUE` |
| استلام مرتين لنفس النقطة | `fuel_batches.trip_stop_id UNIQUE` |

## 6. خريطة الشاشات

- **العميل:** نظرة عامة · طلب نقل (مستند ← تسليم ← مقارنة ← مراجعة) · الرحلات ← تفاصيل الرحلة (خطوات، صور، تأكيد، تقرير PDF) · المشاريع والمواقع · المعدات (استيراد CSV) ← تقرير المعدة · شرائح NFC · جلسة التزويد ← سجل التزويد ← تفاصيل العملية (تصحيح) · الخزانات ← دفتر الخزان (جرد، افتتاحي، تحويل) · الموافقات · التقارير · الإعدادات (المستخدمون، المصفوفة، السياسات، التدقيق) · العقود والمالية (المرحلة الثانية).
- **الناقل:** لوحة · الطلبات والرحلات (قبول/رفض/إسناد) · الأسطول والأسعار.
- **السائق:** رحلاتي ← المهمة (خطوة واحدة واضحة، صور، كميات، ملاحة، اتصال بالمستلم، حالة المزامنة).
- **المستلم:** رحلات موقعي، أو الرابط المحدود `/r/:token`.
- **فيول آب:** الشركات والوثائق والصلاحية ومؤشرات السوق.

## 7. قرارات التكامل والعتاد

- **NFC:** المعرف المقروء هو الرقم التسلسلي للشريحة (UID) ولا يُكتب عليها أي بيان عن العميل. القراءة عبر Web NFC (Chrome Android). iOS لا يدعم Web NFC — يلزم تطبيق أصلي أو قارئ خارجي إن كان iOS ضمن الأجهزة المستهدفة. الشرائح ذات التحقق التشفيري (NTAG 424 DNA مثلًا) تُقيّم بعد اختبار القراءة على الأسطح المعدنية مع فريق السلامة.
- **أرامكو:** المسار الحالي ملف مرفوع من العميل. نقطة التوسع: `services/documents.js` (استبدال مصدر الاستخراج بتكامل معتمد عند توفره).
- **المضخات والعدادات:** الحقل `measure_source` يفصل القراءة اليدوية عن المتصلة؛ الربط بالمضخة مسار اختياري مستقل بعد اعتماد العتاد.
- **الملفات:** تخزين خاص، وصول يمر بفحص الصلاحية ويُسجل في `file_access_log`.

## 8. معيار الحمل المبدئي (أهداف اختبار، غير مقيسة بعد)
10 آلاف شركة، 250 ألف أصل، 100 ألف رحلة شهريًا، 10 ملايين سجل تزويد. الفهارس الحالية على (الشركة، التاريخ)، (الأصل، التاريخ)، (الخزان/الدفعة، الحالة)، (الناقل/المركبة، الحالة). عنق الزجاجة المتوقع: حساب الأرصدة بالتجميع عند كل طلب — الحل: جدول أرصدة مُحدّث داخل نفس المعاملة، ونقل التقارير الثقيلة لعمليات خلفية، وPostgreSQL مع تقسيم `fuelings` حسب الشهر.
